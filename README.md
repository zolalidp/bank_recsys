## Метрика

**Основная метрика: MAP@7.**

Сервис отдаёт клиенту ранжированный список продуктов, которых у него ещё нет.
Целевое событие это переход владения продуктом из 0 в 1 между соседними месяцами.
Задача ранжирующая: важно не точное значение вероятности, а позиция реально
купленного продукта в выдаче.

MAP@7 подходит потому, что учитывает порядок рекомендаций (первая позиция ценнее
седьмой) и корректно обрабатывает случаи с несколькими покупками за месяц.
Отсечка 7 соответствует размеру каталога (22 продукта в обучении) и разумному
объёму выдачи в интерфейсе.

По данным EDA среднее число покупок на событие равно 1.26, то есть почти всегда
покупается один продукт. В этом случае MAP@7 вырождается в MRR@7, и качество
определяется тем, насколько высоко модель поднимает единственный верный продукт.

**Почему не альтернативы.** Accuracy и F1 неинформативны при доле позитивов 3.27%:
модель, всегда предсказывающая отсутствие покупки, даёт свыше 96% accuracy.
ROC-AUC оценивает продукты по отдельности и не отвечает на вопрос, какие семь
показать конкретному клиенту. Precision@7 и Recall@7 игнорируют порядок внутри
выдачи. NDCG@7 корректна, но при бинарной релевантности не даёт ничего сверх MAP.
